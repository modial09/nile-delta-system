# S2 data quality report for the Nile Delta project

Stage S2 of the foundation rebuild, written 15 November 2026. Scope: the cleaning path from the saved source files to the inputs of the generating model, src/allocation_model_v4_1.py, and of the forecasting module, src/forecasting.py. The allocation model was not rerun. The model loader was executed on its own, without any solve, so that file values could be compared against the exact inputs the model builds from them. Every check below was run on the files as found on disk on this date; the source register in this folder carries the checksums of the files tested.

## 1. Three records followed end to end

### Trace 1, an area record: wheat in Beheira, winter, 2020 to 2021

* In the source file (register entry 1): 380,591 feddan, source identifier MOA_Winter_2020_2021, Table 2, evidence grade first hand, status published value. Converted in the same row: 159,848.22 hectares, which is 380,591 times 0.42 exactly.
* In the model input, read back from the loader: baseline wheat area for Beheira is 159,848.22 hectares. Identical.
* Cross check inside the panel: the production file gives 1,093,110 tonnes for the same key and the yield file gives 2.872 tons per feddan; 380,591 times 2.872 is 1,093,057 tonnes, within 0.005 percent of the published production, the difference being the rounding of the published yield. Verdict: the record survives the whole path unchanged.

### Trace 2, a yield record: rice in Dakahlia, summer, 2020 to 2021

* In the source file (register entry 3): 4.014 tons per feddan as published, converted in the same row to 9.557 tonnes per hectare by division by 0.42 (the stored converted value is rounded at the third decimal; the exact quotient is 9.5571).
* In the model input: the published yield map holds 9.557 tonnes per hectare for rice in Dakahlia. Identical to the file.
* In the reference tonnage: Dakahlia rice area of 136,606.26 hectares (from the 2019 to 2020 row set; the 2020 to 2021 area sits in the same panel) times this yield enters the rice reference of 4,086,080 tonnes. Verdict: the record survives unchanged, and the foundation text value of 9.56 for this cell is the same number rounded.

### Trace 3, a price record: wheat, 2023 into the 2024 model price

* In the source file (register entry 10): wheat producer price for 2023 is 10,000 pounds per tonne in the pounds element (and 326.5 in the dollars element, which the forecasting loader correctly excludes by filtering on the unit).
* Through the forecasting module: the drift model, selected by rolling origin backtest over 1991 to 2023, produces a 2024 forecast of 10,296.94 pounds per tonne with a band of 9,500.80 to 12,951.11, written to forecast_prices_yields_v4.csv.
* In the model input: the wheat price layers read back from the loader are low 9,500.80, expected 10,296.94, high 12,951.11. Identical to the forecast file.
* The break in this trace is not in the arithmetic. It is in the vintage: an observed 2024 wheat price of 17,380 pounds per tonne exists in the December 2025 FAOSTAT vintage and was recorded in the second mining sweep, but it was never written into the prices file, so the model consumes a forecast of a year that is already observed. See finding 1.

## 2. What reproduces from the saved originals

* Panel integrity. The area, production and yield files hold 176 rows each, with zero duplicate keys on governorate, crop, season and agricultural year, and identical key sets across the three files, so every join the loader implies is one to one with no unmatched record and no row count change. Area conversion is exact on every row (largest error zero hectares). Yield conversion matches the exact quotient within 0.0005 tonnes per hectare everywhere, the storage rounding named in the register. On the 106 rows where production, area and a published yield all exist, production equals area times yield within 0.017 percent at worst.
* Land totals. The 2020 to 2021 cultivated area sums to 1,676,580.36 hectares and total cropped area to 3,176,473.86 hectares, matching the foundation figures of 1,676,580 and 3,176,474.
* Yield aggregates. Production weighted mean yields for 2020 to 2021, computed from the panel in this audit, are wheat 6.87, rice 9.14, summer maize 8.79, sugar beet 49.37 and potatoes 28.39 tonnes per hectare, matching foundation Section 7 exactly.
* Costs. The addition check (cost without rent plus rent equals cost including rent) passes on all 16 rows of the cost bulletin file, and the per hectare conversions are exact. The seven 2022 constants inside the model code match the file to the cent: wheat 37,742.86; sugar beet 39,454.76; rice 41,850.00; summer maize 37,671.43; Nili maize 37,888.10; summer potatoes 86,657.14; Nili potatoes 54,176.19.
* Water duties. The six duty constants in the code match the Abdelwahab rows of the water file exactly (5,126; 16,600; 9,305; 7,433; 4,079; 6,145 cubic metres per hectare), and the Nili maize constant matches the source note value of 3,122 cubic metres per feddan divided by 0.42.
* Response factors. The four verified Ky constants match the Ky file (wheat 1.05, maize 1.25, sugar beet 1.00, potatoes 1.10).
* Inflow record. The series file recomputes exactly: 100 years, sum 9,193.5 billion cubic metres, mean 91.935, sample standard deviation 16.92, minimum 45.6 in 1913, maximum 137.0 in 1879, matching the foundation statistics. The loader band counts (23 dry, 45 normal, 32 high) and ratios (0.7807, 0.9547, 1.2213) match foundation Derivation A. Inflow probabilities sum to one, and the twelve scenario probabilities sum to one.
* Extractions. The potato season split reconciles to its control total: winter 143,926 plus summer 96,139 plus Nili 1,252 feddan equals the Table 75 all seasons pattern for the eight governorates. In the Nili maize file, the white and yellow Delta sums (40,168 and 29,886 feddan) add to 70,054 feddan, exactly the sum of the published combined rows.
* Missing values in the files. Every absent source value tested is carried as an empty cell with an explicit status, never as zero: Menoufia rice 2020 to 2021 in the area and yield files (status not reported in source table); Nili maize for four governorates; Nili potatoes for seven governorates; winter potato cost cells and Nili potato water cells in the potato split file, which name their gaps in the source column. The distinction between missing, not reported and not covered is preserved in the files themselves.
* The Arabic label fault. Verified as documented: in the tons version of Table 27 of the 2020 to 2021 summer bulletin, the English labels on the two smallest Lower Egypt rows are shifted (the Sharkia row printed as Damietta, the Suez row as Sharkia). The delivered file follows the Arabic labels and the ardab version, and its internal evidence agrees: the 241 feddan row sits under Sharkia, and the white plus yellow parts reconcile with the combined rows. The correction is recorded in EXTRACTIONS_1B.md with its reasoning, not applied silently.
* The two flagged outliers. Verified in the direct crops pull: maize yield 2019 is 4.9513 tonnes per hectare against 7.5162 in 2018 and 7.7767 in 2020, on an area that jumps to 1,533,571 hectares with production almost unchanged; sugar beet yield 2020 is 72.8148 against 48.1588 in 2019 and 49.4826 in 2021. Both rows carry flag A (official figure) in the source, both are kept exactly as published, both are declared in a named constant in the forecasting code, and the backtest machinery computes scores with the outlier origin removed so the effect is measurable. No silent smoothing exists anywhere on this path.
* WaPOR pipeline. The methods note records that monthly volumes sum to the annual volumes within 0.001 percent in every cell, and that a full rerun from the catalogue reproduced the annual totals exactly. The file itself carries the Delta total as an explicit row (24.378 billion cubic metres for 2023), matching the methods note range of 24.081 to 24.802 across 2018 to 2025.
* Saved plans. The version 4.1 plan files hold 184 rows each at full precision, and the robustness plan file is byte for byte identical to the floor 80 plan file, which is correct: the robustness plan is the floor 80 plan.

## 3. Exceptions, most serious first

### Finding 1. The price layer rests on a superseded vintage, and the foundation text says otherwise

The prices file on disk ends at 2023. The December 2025 FAOSTAT vintage, already pulled for crops and already mined for prices in the second sweep, holds observed 2024 farm gate prices: wheat 17,380, maize 19,942 and potatoes 10,446 pounds per tonne. No updated prices file was saved, so the forecasting module forecast 2024 from the older series and the model runs on those forecasts: wheat 10,296.94 against an observed 17,380 (41 percent below), maize 14,836.22 against 19,942 (26 percent below), potatoes 8,405.44 against 10,446 (20 percent below). Foundation Section 4 states that wheat, maize and potatoes now run to 2024 in the December 2025 vintage. That statement is true of the sweep notes and false of the file the model reads. Every margin, frontier cost and water value in the paper inherits prices that are one vintage behind a published observation. Repair is mechanical: save the December 2025 prices extract as the prices file, rerun the forecasting module with 2024 as an observed year, and restate the price target year. Until then, the price layer status is forecast where observation exists.

### Finding 2. One run combines four different years, and the price and yield target years differ from each other

Prices are forecast for 2024. Yield bands are forecast for 2025 (the yield series runs to 2024, one year beyond the price series, because the two files come from different vintages). Costs are observed 2022. Baseline areas and district yields are observed 2020 to 2021, with potato areas and yields from 2021 to 2022. The code header states the price and cost basis honestly, but no document states that the price target year (2024) and the yield target year (2025) differ, and the composite is easy to misread as a single year model. The margins are therefore a stated composite of 2024 prices, 2025 yield uncertainty, 2022 costs and a 2020 to 2021 land pattern, in nominal pounds throughout. This is defensible only while it is stated exactly; at present it is stated in pieces.

### Finding 3. The satellite layer never enters the model, although the foundation says it calibrates the water side

Foundation Section 3 states that the WaPOR product calibrates the water side of the allocation model and replaces the net to applied conversion. In the code, the WaPOR file is read once, inside the header printing routine, to produce a comparison table, with the explicit statement that no scalar is derived from it. The water budget remains the 11.00 billion cubic metre calibration and the duties remain the applied table of the water file. The comparison itself is sound and honestly labelled (whole governorate consumption against modeled crops only, on different bases), but the foundation text overstates the build: satellite data validates nothing numerically in the generating run, because no parameter depends on it. Either the foundation text must be corrected to say validation only, or a later build must state a defensible calibration rule. On the files held, no such rule exists, because the WaPOR product has no cropland mask and cannot be split by crop.

### Finding 4. The drought state is not the driest state

The drought budget is 9.580 billion cubic metres, above the dry budget of 8.588. The construction is faithful to the record: the lowest ten year window mean ratio (0.8709) is higher than the mean ratio of single dry years (0.7807), because a ten year average smooths the single worst years. But any sentence that presents the drought state as the most severe water state, or that reads floor performance in the drought state as the binding test, is wrong on the model's own numbers. The binding state for every floor is the dry state. The paper and any summary must carry the drought state as a persistence state with a milder annual budget.

### Finding 5. The band the model prices is not the band the forecasting module built

The forecasting module builds its band from the 10th and 90th percentile backtest errors. The allocation model assigns the low and high states probabilities of 0.25 each and describes the reading, in its own header, as treating the band as quartiles. A 10th percentile edge is not a quartile. The expected values of every stochastic output therefore rest on a probability reading that contradicts the band construction in the feeding module. One of the two conventions must change, and the change belongs to whichever stage owns the scenario definition; S2 records the mismatch without choosing.

### Finding 6. The Menoufia rice fill pairs an area from one year with a yield from a different construction

The loader substitutes the 2019 to 2020 Menoufia rice area (19 feddan, 7.98 hectares) for the absent 2020 to 2021 cell, which is stated in the code. It then pairs that area with the filled yield of 9.138 tonnes per hectare, the area weighted mean of the other seven governorates, although Menoufia has a published yield for the very year the area came from (8.395 tonnes per hectare in 2019 to 2020) sitting unused in the yield file. The tonnage at stake is about 73 tonnes against a rice reference of 4,086,080 tonnes, so no headline moves. The defect is methodological: the fill rule for yields runs before, and independently of, the year substitution for areas, and the two rules were never reconciled. A reader auditing the baseline cell by cell will find one cell whose area and yield come from different years and different constructions, with the pairing stated nowhere.

### Finding 7. Yield fills exist only in code and logs, not in any data file

Twelve district yield cells are filled by the loader (listed in the parameter dictionary). The data files correctly carry those cells as empty with a not reported status, but the filled values that the model actually uses appear only in the code path and in run log text. Anyone who recomputes the reference tonnage from the CSV files alone, treating empty as absent, gets a different baseline from the model's, and nothing in the data folder tells them why. The fill rule is defensible; its invisibility in the data layer is not. The fills should be written to a file with their rule, or the dictionary entry must travel with the data.

### Finding 8. Model parameters bypass the files as hard coded constants

Costs, water duties, response factors, cap shares and the beet factory price are constants inside the model code, transcribed from the CSV files. S2 verified every constant against its file and all agree today. Nothing enforces the agreement: an edit to a file changes nothing in the model, and an edit to a constant leaves the file silently stale. For a project whose claim is traceability, the parameter set should be read from the files, or the constants should carry the checksum of the file they were transcribed from.

### Finding 9. Three recorded checks cannot be replayed from the delivered files

The prices file mirror comparison (the mirror was not retained), the CAPMAS income bulletin arithmetic check (the revenue and net return columns were not carried into production_costs_egypt.csv, so revenue minus cost cannot be rechecked), and the CAPMAS 2016 to 2017 edition provenance (its download address could not be reopened in the skeptic pass and rests on the research record). None of these is evidence of a wrong value; the prices series is corroborated by the CAPMAS income bulletin at overlapping points and the costs by the Ministry bulletin at 2016 to 2017. But the register must mark them as asserted checks, not reproducible ones.

### Finding 10. The panel files mix evidence grades without a summary, and their names mislead

Of the 176 rows in each panel file, 112 are first hand and 64 are second hand (the Menoufia 2021 to 2022 and 2022 to 2023 series), and 56 rows are placeholders with the status not covered by this source. The grades and statuses are carried on every row, which is correct practice, but no summary in the data folder states the mix, and the file names begin with capmas although the data is Ministry bulletin data, a risk the foundation itself flags. The model reads only the 2020 to 2021 and 2019 to 2020 rows, so no second hand row enters the generating run; the risk is to a future reader, not to the current numbers.

### Finding 11. Two project documents contradict the files they describe

data/SOURCES.md still describes the version 1 state: prices and the district land base marked as to pull, and the version 1 calibration described as current. It is contradicted by the files on disk and should be retired or rewritten; this register supersedes it. Separately, src/data_loading.py is a stub in which every loader raises NotImplementedError, while its docstring claims that every number in the paper can be traced through it. The real loading lives inside the model and forecasting modules. The stub is harmless to the numbers and false as documentation.

### Finding 12. Small items recorded for completeness

* The WaPOR file carries a Delta total row inside the data table as a ninth governorate entry. The model ignores it correctly by name matching, but any plain sum over the file double counts the Delta. The methods note totals are the correct ones.
* The yield file stores converted yields rounded; the largest deviation from the exact conversion is 0.0005 tonnes per hectare. Immaterial.
* Sugar beet yield in the crops file begins in 1979, because the source publishes zero area and no yield before then. Yield backtests for sugar beet therefore rest on a shorter history than the other crops, which the backtest file reflects.
* The prices file carries both the pounds and dollars elements under the same crop and year keys. The forecasting loader filters on the unit, verified in the code, so no double counting occurs; a reader joining the file without that filter would double every year.
* The summer 2020 potato cost rows carry the highest identification risk in the cost file, because the Ministry PDF text layer is garbled; the extraction note flags them for one visual check of the printed page, which has not been recorded as done. The model uses the summer 2022 potato rows, not the 2020 rows, so the risk does not touch the generating run.

## 4. Verdict for the stage gate

The cleaning path itself is in good order: keys are unique, joins are one to one, conversions are exact, missing values are never silently zeroed, the one source fault found was corrected from the Arabic original with its reasoning recorded, and the two outliers stand as published with their effect made measurable. What does not reproduce is not the cleaning but the currency of two inputs and the honesty of two descriptions: the price layer is one vintage behind a published observation (finding 1), the run composite spans four years with mismatched price and yield target years (finding 2), the satellite layer is described as calibration and functions as decoration (finding 3), and the scenario probabilities read the forecast band under a convention the forecasting module does not use (finding 5). Under the S2 acceptance rule, no important missing cell or unit conflict enters the primary case silently; the exceptions above are the ones that must be settled or restated before the primary case is described as settled.
